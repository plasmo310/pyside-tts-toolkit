TTS Toolkit

ローカルで動く 3 つの音声合成モデルを、同じコマンド・同じ引数で呼べるようにしたサンプル。 依存が互いに衝突する 3 つのモデルをプロセス境界で隔離し、共通のラッパー越しに扱う。 文章からオリジナルの声を設計し、キャラクター台本から会話をまとめて生成できる。

qwen
Qwen3-TTS 1.7B
日英とも高品質。3 秒の参照音声からクローンできる総合第一候補。
24 kHz  ·  Apache-2.0
chatterbox
Chatterbox Multilingual V3
0.5B と軽く生成も速い。23 言語対応で、まず試すならこれ。
24 kHz  ·  MIT
irodori
Irodori-TTS v4.1 Small
日本語専用・48 kHz。文章で声を設計でき、絵文字で感情も乗る。
48 kHz  ·  MIT
設計

なぜモデルごとに環境を分けるのか

3 つのモデルは transformers と torch のバージョン指定が 互いに排他的で、1 つの仮想環境には物理的に同居できない。 extras で切り替える単一環境という構成は最初から成立しない。

エンジン 入手方法 transformers torch
qwen pip install qwen-tts ==4.57.3 2.11.0+cu128
chatterbox git+github (V3 は master のみ) ==5.2.0 2.6.0 → 2.7.1+cu128
irodori git clone (PyPI 未公開) >=5.12.1,<6 2.10.0+cu128

そこで共通層はモデルを直接読み込まず、エンジンごとの仮想環境にある runner.py をサブプロセスとして起動し、標準入出力の JSON でやり取りする。 共通層自体は torch に一切依存しない。

CLI ／ GUI
.venvs/common ／ torch に依存しない共通層
標準入出力 ／ 1 行 1 JSON ／ UTF-8
qwen
.venvs/engine-qwen
transformers 4.57.3
chatterbox
.venvs/engine-chatterbox
transformers 5.2.0
irodori
.venvs/engine-irodori
transformers 5.12.1

この境界が効いているのは次の点。

  • モデルを足しても既存の環境が壊れない
  • 共通層が軽いまま保たれ、GUI や Remotion 連携からそのまま使える
  • runner はモデルを読み込んだまま常駐するので、バッチで読み込みを繰り返さない
  • 対応外のパラメータはモデルを読み込む前に共通層で弾ける
将来 HTTP サーバ方式に移る場合

Irodori には公式の OpenAI 互換サーバ（POST /v1/audio/speech）がある。 そちらに切り替えたくなっても、TTSEngine を実装したバックエンドを 足すだけで呼び出し側のコードは変わらない。

セットアップ

一から動かすまで

必要なもの: mise ／ uv ／ git ／ NVIDIA GPU（CUDA 12.8 以降のドライバ、VRAM 8GB 以上推奨）。 ライブラリは Python 本体には一切入れず、すべて uv が作る仮想環境に入る。

所要時間とディスク

仮想環境 3 つが CUDA 版 PyTorch を個別に持つため、ダウンロードは 10GB を超える。 さらに初回の合成時にモデル重み（合計 10GB 前後）を取得する。 全体で 1 時間以上かかることがある。空きディスクは 30GB 以上。

  1. 一括セットアップ

    Python 3.12 の用意から 3 エンジン分の仮想環境構築までが 1 コマンドで終わる。

    PowerShell
    > git clone <このリポジトリ>
> cd python-tts-sample
> pwsh scripts\win\setup_engines.ps1

    エンジンを選んで実行することもできる：
    pwsh scripts\win\setup_engines.ps1 -Targets common,chatterbox

  2. 環境を確認する

    各エンジンの仮想環境の中で torch を読み込み、GPU のアーキテクチャに対応したビルドかまで見る。

    tts doctor
    > .\.venvs\common\Scripts\python.exe -m ttstoolkit.cli.doctor

== GPU ==
NVIDIA GeForce RTX 5070, 12227 MiB, 2215 MiB, 595.79

== Engines ==

[chatterbox] ResembleAI/chatterbox (multilingual v3)
  torch 2.7.1+cu128 / CUDA ok / NVIDIA GeForce RTX 5070

[irodori] Aratako/Irodori-TTS-v4.1-Small
  torch 2.10.0+cu128 / CUDA ok / NVIDIA GeForce RTX 5070

[qwen] Qwen/Qwen3-TTS-12Hz-1.7B-Base
  torch 2.11.0+cu128 / CUDA ok / NVIDIA GeForce RTX 5070

    CUDA ok が 3 つ出れば準備完了。

  3. 最初の 1 本を合成する

    最も軽い chatterbox から試すのが早い。

    PowerShell
    > .\.venvs\common\Scripts\python.exe -m ttstoolkit.cli.synth -e chatterbox -t "こんにちは。" -l ja -O hello.wav

[info] Engine chatterbox is ready (ResembleAI/chatterbox multilingual v3)
wrote D:\...\output\hello.wav
  model    ResembleAI/chatterbox multilingual v3
  audio    24000 Hz / 2.96s
  took     5.39s

    以降のコマンドはリポジトリのルートで実行する。 サブコマンド名を受け取る関数を定義しておくと楽になる （Set-Alias は引数を渡せないので関数にする）。

    PowerShell
    > function tts {
>>     $exe = "$PWD\.venvs\common\Scripts\python.exe"
>>     & $exe -m "ttstoolkit.cli.$($args[0])" @($args | Select-Object -Skip 1)
>> }
GUI

画面から使う

最低限の操作は GUI (PySide6) からできる。合成そのものは CLI と同じ ttstoolkit.engine を呼ぶだけなので、 画面からできることと CLI からできることは常に一致する。

起動
> scripts\win\LaunchApp.bat
タブすることCLI では
Synthesis テキストを 1 件合成する。声はプリセット／クローン／文章から選ぶ tts synth
Voice Design 文章から声を作り input/voices/ に残す tts synth --voice-design
Script キャスト定義と台本からまとめて合成する tts script

合成は別スレッドで走るので画面は固まらない。進捗は下のログ欄に流れ、 内容は CLI が標準エラーへ出しているものと同じ。入力値とウィンドウの 位置・サイズは終了時に保存され、次の起動で戻る。

キャンセルは次の台詞から効く

生成中の 1 件を途中で止める手段がモデル側に無いため、 Cancel は次の 1 件に入る前に効く協調式にしている。

使い方

基本の呼び出し方

1 件だけ合成する

tts synth
# テキストを直接
> tts synth -e qwen -t "こんにちは。" -l ja -O a.wav

# 長い台本はファイルから（UTF-8）
> tts synth -e irodori -f script.txt -l ja -O b.wav

# 結果を再現したいときはシードを固定
> tts synth -e chatterbox -t "テスト" -l ja --seed 42 -O c.wav

# 話速の指定は irodori のみ（1.0 が等速、小さいほどゆっくり）
> tts synth -e irodori -t "ゆっくり話します。" -l ja --speed 0.8 -O slow.wav

声をクローンする

参照音声を -r で渡すだけ。3 エンジンとも対応している。

tts synth -r
# chatterbox / irodori は参照音声だけでよい
> tts synth -e chatterbox -t "クローンした声です。" -l ja `
      -r alice.wav -O clone.wav

# qwen は書き起こしも渡すと品質が上がる（ICL モード）
> tts synth -e qwen -t "おはようございます。" -l ja `
      -r alice.wav --reference-text "こんにちは。音声合成のテストです。" `
      -O clone.wav

--reference-text は Qwen でのみ使われる。省略すると話者埋め込みだけを使う モードに自動で落ちるが、そのぶん似なくなる。参照音声の長さの目安は次の通り。

エンジン参照音声の長さ書き起こし
qwen3 秒〜あると品質が上がる
chatterbox10 秒前後不要
irodori30 秒以上を推奨（上限 120 秒）不要

いずれもノイズ・BGM のないきれいな音声を使う。

まとめて合成する（バッチ）

モデルを 1 回だけ読み込んで全件を処理するので、1 件ずつ呼ぶより速い。

tts batch
> tts batch -e qwen sample.ja.json -o output\batch

[info] 3 items from D:\...\input\batch\sample.ja.json
[info] Engine chatterbox is ready (ResembleAI/chatterbox multilingual v3)
[1/3] line-001   2.80s  こんにちは。今日はいい天気ですね。
[2/3] line-002   2.60s  音声合成のバッチ処理を試しています。
[3/3] line-003   4.00s  モデルは常駐しているので、二件目以降は速く生成…
[info] wrote output\batch\manifest.json
[info] 3/3 succeeded

入力 JSON

input/batch/sample.ja.json
[
  {"id": "line-001", "text": "こんにちは。", "language": "ja"},
  {"id": "line-002", "text": "今日はいい天気ですね。", "language": "ja", "seed": 42},
  {"id": "line-003", "text": "クローンもできます。", "language": "ja",
   "reference_audio": "ref/alice.wav"}
]

使えるキーは id / text / language / reference_audio / reference_text / seed / speed。 reference_audio は入力 JSON からの相対パスで解決される。 1 件失敗しても残りを続けたいときは --keep-going を付ける。

出力の manifest

outdir/{id}.wav と一緒に manifest.json が出る。 各件の尺・サンプリングレート・使ったモデルが入るので、Remotion など下流から 音声の長さを知りたいときに使える。

output/batch/manifest.json
{
  "engine": "irodori",
  "total_elapsed_sec": 27.406,
  "items": [
    {
      "id": "line-001",
      "text": "こんにちは。今日はいい天気ですね。",
      "sample_rate": 48000,
      "duration_sec": 3.68,
      "model_id": "Aratako/Irodori-TTS-v4.1-Small",
      "elapsed_sec": 3.829
    }
  ],
  "failures": []
}

Python から呼ぶ

Python
from ttstoolkit.engine.registry import create_engine
from ttstoolkit.engine.types import SynthesisRequest

with create_engine("irodori") as engine:
    result = engine.synthesize(
        SynthesisRequest(
            text="こんにちは。",
            output_path="output/hello.wav",
            language="ja",
            seed=42,
        )
    )
    print(result.sample_rate, result.duration_sec)

with を抜けるまでモデルは常駐する。複数件を投げるなら 1 つの with の中で回す。

声を作る

オリジナルの声を設計して固定する

文章で声の特徴を書くと、実在の人物に依存しないキャラクターの声を作れる。 ただし Voice Design は生成のたびに声が揺れるので、 気に入った声は一度「マスター音声」に落として固定し、以後はそれをクローンする。 こうすると声が安定し、英語など別のエンジンを使う場面にも同じ声を持ち込める。

1
文章で声を設計する
--voice-design で何本か試す
2
マスター音声を作る
長めの台詞で 1 本だけ生成して保存
3
以後はクローンして使う
-r にマスター音声を渡す
4
英語版も同じ声で
マスター音声を Qwen / Chatterbox へ
① 声を試す　→　② 固定する　→　③ クローンする
# ① 指示文を変えながら何本か作って聴き比べる（seed は固定しておく）
> tts synth -e irodori --seed 42 -l ja `
      --voice-design "落ち着いた低めの女性の声。丁寧で穏やかな話し方。" `
      -t "この声でどうでしょうか。" -o input\voices -O try01.wav

# ② 気に入ったら長めの台詞でマスター音声を 1 本作る（30 秒以上あると安定）
> tts synth -e irodori --seed 42 -l ja `
      --voice-design "落ち着いた低めの女性の声。丁寧で穏やかな話し方。" `
      -f input\voices\master_script.txt -o input\voices -O reimu_master.wav

# ③ 以降は -r でクローンする（声がぶれない）
> tts synth -e irodori -r input\voices\reimu_master.wav `
      -t "マスター音声から再現した声です。" -l ja -O a.wav

# ④ 英語版は同じマスター音声を Qwen に渡す
> tts synth -e qwen -l en -r input\voices\reimu_master.wav `
      --reference-text "こんにちは。私はこのキャラクターの声です。" `
      -t "This is the same character speaking English." -O en.wav

指示文の書き方

効くのは次の軸。全部を詰め込むより 3〜4 要素に絞るほうが安定する。

軸例
性別・年齢若い女性、少年、中年の男性、老人
声の高さ・質低め、高め、掠れた、澄んだ、ハスキー、太い
話し方丁寧、ぶっきらぼう、早口、ゆっくり、淡々と
感情・態度楽しそうに、呆れたように、落ち着いて、緊張気味に
シードと指示文は切り分けて振る

--seed を固定して指示文だけ変えれば、声の違いが指示文によるものだと 分かる。逆に指示文を固定してシードを振ると、同じ方向性で別の声が出る。 採用した指示文とシードは cast.toml に控えておくと作り直せる。

エンジンごとの違い

エンジンVoice Design指示の言語備考
irodori ○日本語 日本語キャラクターの第一候補。参照音声と併用できる（声質は参照音声、話し方は指示文）
qwen ○英語推奨 専用チェックポイントを使う。-r とは併用不可
chatterbox ×— 参照音声からのクローンのみ。渡すと明示エラー

指示文の例、キャラクターを増やす流れ、収録した実在の声を使う場合の注意は docs/guide/original-voice.md にまとめてある。

台本

キャラクター台本からまとめて生成する

複数のキャラクターが会話する台本を書いて、台詞ごとの wav を一度に作る。 声の定義と台詞を別ファイルに分けるのがこの機能の要で、 台詞は毎回書くが声を決めるのは最初の一度きりだから、台本側には 「誰が」「何を」しか書かない。

cast.toml — 最初に一度だけ書く
# 日本語名は TOML の仕様上クォートが必要
[voices."霊夢"]
engine = "irodori"
voice_design = "落ち着いた少女の声。淡々と話す。"
language = "ja"
seed = 42

[voices."魔理沙"]
engine = "irodori"
reference_audio = "../../input/voices/marisa.wav"
language = "ja"

[voices."ナレーター"]
engine = "qwen"
language = "ja"
ep01.ja.txt — 毎回書く
# ■ オープニング

ナレーター: ある晴れた日のこと。

霊夢: 今日はいい天気ね。
魔理沙: そうだな、絶好の弾幕日和だぜ！

# ■ 本編

霊夢[speed=0.9]: ……また変なこと言ってる。
魔理沙[id=punchline]: やった、ごちそうさま！

# インデントで長い台詞を折り返せる
霊夢: まあいいわ。
  お茶でも淹れてくるから、
  そこで待ってなさい。
tts script

台本の書き方

書き方意味
話者: 台詞1 行 1 台詞。コロンは半角 : でも全角 ： でもよい
# コメント行頭の # は無視される。セクションの見出しに使う
（空行）無視される。場面の区切りに自由に入れてよい
　　インデント行直前の台詞の続き。区切り文字なしで連結されるので日本語に余計な空白が入らない
話者[key=値]: 台詞その台詞だけ上書き。id / speed / seed / lang

英語の台詞はインデント継続だと単語がくっつくので、1 行に収めるか行末に空白を置く。 未知の話者名・未知のオプション・重複した id はすべて行番号つきのエラーになる。

出力と Remotion 連携

ファイル名の先頭が台本の並び順になる。manifest.json には 先頭からの累積オフセット（start_sec）が入るので、 Remotion の <Sequence from={...}> にそのまま使える。

output/ep01/
001-ナレーター.wav
002-霊夢.wav
003-魔理沙.wav
  …
007-punchline.wav      ← [id=punchline] を付けた台詞
manifest.json

// manifest.json の 1 件
{
  "index": 2,
  "voice": "霊夢",
  "text": "今日はいい天気ね。",
  "start_sec": 2.14,
  "duration_sec": 2.64,
  "sample_rate": 48000,
  "model_id": "Aratako/Irodori-TTS-v4.1-Small"
}
モデルの読み込みは 1 エンジンにつき 1 回

台詞ごとにプロセスを立て直すと読み込み（10〜60 秒）を毎回払うことになるので、 エンジン単位でまとめて処理し、manifest では台本順に並べ直している。 そのため進捗表示はエンジンごとにまとまって出る。 キャラクターを増やしてもエンジンが同じなら追加コストはない。

サンプリングレートは混ざる

Irodori は 48 kHz、Qwen と Chatterbox は 24 kHz。manifest の sample_rate に各ファイルの実際の値が入るので、ffmpeg や Remotion 側でリサンプルさせればよい。揃えたい場合は全キャラクターを 同じエンジンにする。

比較

エンジンの選び方

エンジン 日本語 英語 クローン Voice Design 話速 シード レート ライセンス
qwen ○○○ ○ ×○ 24 kHzApache-2.0
chatterbox ○○○ × ×○ 24 kHzMIT
irodori ○×○ ○ ○○ 48 kHzMIT
  • まず試すなら chatterbox — 0.5B と軽く、生成も速い。
  • 日英を同じ声で出すなら qwen — 1 本で両言語をまかなえる。
  • 日本語のキャラクター性を優先するなら irodori — 48 kHz で表現力が高い。ただし英語は出せない。

対応していないパラメータを渡すと、黙って無視されずエラーになる。 判定は共通層が行うのでモデルを読み込む前に失敗し、待たされない。

対応外は即エラー
> tts synth -e irodori -t "Hello." -l en -O x.wav
[error] Engine 'irodori' does not support language 'en' (supported: ja)

> tts synth -e chatterbox -t "テスト" --speed 1.5 -O x.wav
[error] Engine 'chatterbox' does not support speed (speed=1.5); leave it at 1.0

日英の両方が要る場合

Irodori は英語を出せないので、二段構えにする。

  • Irodori の Voice Design で日本語のキャラクター声を作る
  • その音声を「マスター音声」として保存する
  • 英語版はマスター音声を -r に渡して Qwen か Chatterbox で生成する
日英を同じ声で出す
# 日本語（Irodori）
> tts synth -e irodori -t "こんにちは。" -l ja -O ja.wav

# 英語（同じ声でクローン）
> tts synth -e qwen -t "Hello." -l en `
      -r output\ja.wav --reference-text "こんにちは。" -O en.wav

日英で音響モデルが違うので、同一人物に聞こえるかは必ず耳で確認すること。

設定を変える

python/ttstoolkit/tool_config.py にエンジンごとの設定がある。 仮想環境を作り直す必要はなく、編集すれば次の実行から反映される。

python/ttstoolkit/tool_config.py（抜粋）
ENGINE_DEFINITIONS = {
    "qwen": EngineSpec(
        ...
        options={
            # VRAM 不足なら 0.6B に
            "base_model": "Qwen/Qwen3-TTS-12Hz-1.7B-Base",
            "dtype": "bfloat16",
            # 声の指定が無いときのプリセット話者
            "speakers": {"ja": "ono_anna", "en": "ryan"},
        },
    ),
    "chatterbox": EngineSpec(
        options={"cfg_weight": 0.5},   # 上げると読み飛ばしが減る
    ),
    "irodori": EngineSpec(
        options={"num_steps": 24},     # 下げると速く、上げると高品質
    ),
}

声そのものは設定ではなく --voice-design で指定する。 Irodori はさらに、本文に絵文字を入れると笑い・ため息なども表現する。

困ったとき

よくある詰まりどころ

症状対処
not set up と表示される そのエンジンの仮想環境がまだ無い。tts engines で確認し、 pwsh scripts\win\setup_engines.ps1 -Targets irodori で個別に作り直す。
生成が遅い／CPU で動いている気がする tts doctor で CUDA unavailable と出ていないか確認する。 ドライバのバージョンと nvidia-smi が動くかを見る。
VRAM が足りない（OOM） tool_config.py の Qwen のモデル ID を 0.6B 版に変える。 複数エンジンを同時に動かさない。
no kernel image is available torch が GPU 世代に対応していない。tts doctor で torch のバージョンを確認し、古ければ仮想環境を作り直す。
エラーの詳細が見たい -v / --verbose を付けるとエンジン側のログがそのまま流れる。
時間がかかりすぎてタイムアウトする TTS_READY_TIMEOUT（既定 1800 秒・モデル読み込み）と TTS_SYNTH_TIMEOUT（既定 900 秒・1 件の合成）で延ばせる。
日本語が文字化けする ターミナルのコードページを確認する（chcp 65001）。 コマンドとエンジンのやり取り自体は UTF-8 に固定してある。
