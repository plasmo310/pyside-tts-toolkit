TTS Toolkit 使い方

セットアップが済んだ状態から、やりたいことごとに引くためのページ。 導入手順は docs/setup/ を参照。

準備 最初に一度

コマンドはすべてリポジトリのルートで実行する。 パスが長いので、関数を 1 つ作っておく （Set-Alias は引数を渡せないので関数にする）。

PowerShell（このシェルの間だけ有効）
> cd python-tts-sample
> function tts { & "$PWD\.venvs\common\Scripts\python.exe" -m ttstoolkit.cli @args }

環境が正しいか確認する。CUDA ok が 3 つ出れば準備完了。

動作確認
> tts doctor
> tts engines   # エンジン一覧と対応機能
input/voices/ 参照音声（マスター音声）の置き場 input/script/ キャスト定義と台本 input/batch/ バッチ入力 JSON output/ 生成した wav の置き場
パスはファイル名だけでよい

相対パスは「カレント → リポジトリのルート → 種類ごとの既定の置き場」の 順に探される。参照音声なら input/voices/、台本なら input/script/ から拾うので、 -r master.wav のように書ける。

GUI で試す 画面から

最低限の操作は画面からできる。合成そのものは CLI と同じものを呼ぶので、 画面からできることと CLI からできることは一致する。

起動
> scripts\win\LaunchApp.bat
タブすることCLI では
Synthesisテキストを 1 件合成するtts synth
Voice Design文章から声を作り input/voices/ に残すtts synth --voice-design
Script台本からまとめて合成するtts script

合成は別スレッドで走るので画面は固まらない。進捗は下のログ欄に流れ、 入力値とウィンドウの位置は終了時に保存されて次の起動で戻る。

Cancel はすぐには効かない

生成中の 1 件を途中で止める手段がモデル側に無いので、キャンセルは 次の台詞に入る前に効く。1 件だけの合成では最後まで走る。

1 本しゃべらせる tts synth

いちばん基本の形。まずは軽い chatterbox で試すのが早い。

最短
> tts synth -e chatterbox -t "こんにちは。音声合成のテストです。" -l ja

[info] Engine chatterbox is ready (ResembleAI/chatterbox multilingual v3)
wrote D:\...\output\chatterbox-7a1c93e2f508.wav
  model    ResembleAI/chatterbox multilingual v3
  audio    24000 Hz / 2.96s
  took     5.39s

-O を省くとテキストから決まる名前になる。名前を決めたいときは付ける。

出力先を決める・長い文はファイルから（UTF-8）
> tts synth -e qwen -t "こんにちは。" -l ja -O hello.wav
> tts synth -e irodori -f script.txt -l ja -o output\ep01
引数内容
-e / --engine必須。 qwen / chatterbox / irodori
-t / --text読み上げるテキスト
-f / --text-fileテキストをファイルから読む
-O / --output出力ファイル名
-o / --output-dir書き出し先（既定 output/）
-l / --languageja / en
-r / --reference参照音声（クローン）
--voice-design文章で声を指定する
--seed乱数シード
--speed話速（irodori のみ）
-v / --verboseエンジン自身の出力も見る
対応していない指定はエラーになる

黙って無視されることはない。しかもエンジンを起動する前に判定するので、 待たされずに失敗する（tts synth -e irodori -l en は 0.1 秒でエラー）。

オリジナルの声を作る --voice-design

実在の人物に頼らずに、文章の指示だけから声を作れる。ただし 生成のたびに少し揺れるので、気に入った 1 本を「マスター音声」として 残し、以後はそれをクローンして使い回すのが安定する。

  1. 声を試す — 指示文を変えて何本か作って聴き比べる
    seed を固定しておくと、違いが指示文によるものだと分かる
    > tts synth -e irodori -l ja --seed 42 `
>>     --voice-design "落ち着いた低めの女性の声。丁寧で穏やかな話し方。" `
>>     -t "この声でどうでしょうか。名前は霊夢といいます。" `
>>     -o input\voices -O try01.wav
  2. マスター音声にする — 決まったら長めの台詞で 1 本作る
    30 秒以上あると、以後のクローンが安定する
    > tts synth -e irodori -l ja --seed 42 `
>>     --voice-design "落ち着いた低めの女性の声。丁寧で穏やかな話し方。" `
>>     -f input\voices\master_script.txt `
>>     -o input\voices -O reimu_master.wav
  3. 以後はクローンで使う — 声がぶれなくなる
    指示文はもう要らない
    > tts synth -e irodori -l ja `
>>     -r reimu_master.wav `
>>     -t "今日も一日がんばりましょう。"

指示文の書き方

全部を詰め込むより、3〜4 要素に絞るほうが安定する。

軸例
性別・年齢若い女性、少年、中年の男性、老人
声の高さ・質低め、高め、掠れた、澄んだ、ハスキー、太い
話し方丁寧、ぶっきらぼう、早口、ゆっくり、淡々と
感情・態度楽しそうに、呆れたように、落ち着いて、緊張気味に
エンジンごとの制約

chatterbox は Voice Design に非対応（クローンのみ）。 qwen は --voice-design と -r を併用できない。 irodori は併用でき、そのときは声質＝参照音声・話し方＝指示文になる。 日本語の声を作るなら irodori が確実。

声をクローンする -r / --reference

手元の音声から声を複製する。参照音声は input/voices/ から探される。

基本
> tts synth -e qwen -l ja `
>>     -r master.wav `
>>     -t "参照音声からクローンした声で話しています。"
Qwen は書き起こしがあると品質が上がる
> tts synth -e qwen -l ja `
>>     -r master.wav --reference-text "参照音声で話している内容" `
>>     -t "おはようございます。"
エンジン参照音声の長さ書き起こし
qwen3 秒〜あると品質が上がる
chatterbox10 秒前後不要
irodori30 秒以上を推奨（上限 120 秒）不要

いずれもノイズ・BGM のないきれいな音声を使う。

日英で同じ声を出す

irodori は日本語しか出せない。日本語版は irodori で作り、 同じマスター音声を -r に渡して qwen か chatterbox で 英語版を作ると、同じ声のまま二言語を揃えられる。

台本からまとめて作る tts script

声の定義は一度書けば使い回せる。毎回書くのは台詞だけ。 話者ごとにエンジンが違ってもよい。

input/script/cast.toml — 声の定義（最初に一度）
[voices."霊夢"]
engine = "irodori"
voice_design = "落ち着いた少女の声。淡々としていて、少し呆れたような話し方。"
language = "ja"
seed = 42

[voices."魔理沙"]
engine = "irodori"
reference_audio = "../voices/marisa_master.wav"   # cast.toml からの相対
language = "ja"

[voices."ナレーター"]
engine = "qwen"
language = "ja"
seed = 100
日本語のキャラクター名はクォートが必要

TOML の仕様上、クォートなしのテーブル名に使えるのは半角英数字と _ - だけ。[voices.霊夢] は構文エラーになるので [voices."霊夢"] と書く。

input/script/ep01.ja.txt — 台詞（毎回書くのはこれだけ）
# ある晴れた日

霊夢: 今日はいい天気ね。
魔理沙: そうだな、絶好の弾幕日和だぜ！

霊夢[speed=0.9]: ……また変なこと言ってる。
魔理沙[id=punchline]: やった、ごちそうさま！

霊夢: 長い台詞は
  インデントした行で続けられる。

角括弧で id / speed / seed / lang を台詞ごとに上書きできる。 継続行は区切り文字なしで連結される（日本語に余計な空白が入らないように）。

実行
> tts script ep01.ja.txt -c cast.toml -o output\ep01

[info] 7 lines / 3 characters / engines: qwen, irodori
--- qwen (1 lines) ---
[001] ナレーター   1.84s  ある晴れた日のこと。
--- irodori (6 lines) ---
[002] 霊夢         2.64s  今日はいい天気ね。
[003] 魔理沙       3.84s  そうだな、絶好の弾幕日和だぜ！
...
[info] 7/7 lines synthesized
output/ep01/001-ナレーター.wav output/ep01/002-霊夢.wav output/ep01/007-punchline.wav id を付けた台詞 output/ep01/manifest.json 尺と先頭からの秒数

manifest.json の start_sec は先頭からの累積オフセット。 動画側で「この秒から流す」の計算にそのまま使える。 --gap はこの計算に使うだけで、wav に無音は足さない。

JSON からまとめて作る tts batch

キャラクターが要らないなら、こちらのほうが単純。 モデルは 1 回だけロードされ、2 件目以降はロード時間を払わない。

input/batch/sample.ja.json
[
  {"id": "line-001", "text": "こんにちは。", "language": "ja"},
  {"id": "line-002", "text": "今日はいい天気ですね。", "seed": 42}
]
実行
> tts batch -e qwen sample.ja.json -o output\batch
> tts batch -e qwen sample.ja.json --keep-going   # 失敗しても続ける

使えるキーは id / text / language / reference_audio / reference_text / voice_design / seed / speed。 reference_audio は入力 JSON からの相対パスで解決される。

どのエンジンを使うか

エンジン日本語英語クローン 声を作る話速速さ
qwen ○○ ○○ ×遅い
chatterbox ○○ ○× ×速い
irodori ○× ○○ ○速い
やりたいこと選ぶもの
とりあえず動かすchatterbox（いちばん軽い）
日本語キャラクターを作り込むirodori（48 kHz、話速も効く）
英語も出したいqwen か chatterbox
参照音声から高品質にクローンqwen（書き起こしを添える）

困ったとき

症状すること
エンジンが起動しない tts doctor で仮想環境と CUDA を確認する
合成が失敗する -v を付けてエンジン自身の出力を見る
「does not support ...」と言われる tts engines で何が使えるか確認する
生成が途中で切れる 文単位に分けて tts batch で流す
声が毎回変わる --seed を固定する。決まったらマスター音声にしてクローンする
日本語が不自然 irodori に変える（日本語専用で 48 kHz）
VRAM が足りない tool_config.py で qwen を 0.6B に下げる
初回が終わらない モデル重みのダウンロード。合計 10GB 前後かかる

詳しくは docs/cli/（コマンド別）、 docs/gui/usage.md（画面）、 docs/setup/（導入とトラブルシュート）。
