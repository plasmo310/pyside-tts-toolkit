# 調査内容
- TTSについて、現在主要となるサービスをカテゴリ分けして比較やインストール、使用方法などについてまとめてください。
- 用途
	- ゆっくり動画のようにキャラクターにしゃべらせたい。
	- オリジナルキャラクターにしゃべらせたいので声から作りたい。
	- 日本語だけでなく英語もローカライズ版として出したい。
	- Remotionと連携したいので、API経由で扱いたい。
- 追加条件
	- 従量課金サービスは対象外。
	- ローカルで無料・無制限に生成でき、品質がよいものを優先する。
	- Qwen3-TTS / OmniVoice / Fish Speech / Chatterbox / CosyVoice / GPT-SoVITS / F5-TTS / XTTS / Irodori-TTSを比較する。

# 調査結果

> [!info] 調査時点
> 2026-09-21。ここでいう「無料」はAPI従量課金がないことを指す。GPU購入費、電気代、保守工数は別途必要。商用無料かどうかはコードではなく**使用するモデル重みのライセンス**まで確認する。

## 1. 前提：TTSの種類と構成レイヤー

### 1.1 「TTS製品」を構成する5つの層

TTSを比較するときは、アプリ・API・推論エンジン・学習済みモデルを同じものとして扱わないことが重要である。本調査では次のように区別する。

| 層 | 役割 | 例 | 料金・権利で確認する点 |
|---|---|---|---|
| アプリ／統合基盤 | モデル管理、声プロファイル、生成履歴、長文分割、GUIなど | **Voicebox** | アプリ自体のライセンス |
| API／サーバー | Remotionや別アプリからHTTPで呼ぶ窓口 | Voicebox REST API、Irodori-TTS-Server、CosyVoice FastAPI | ローカル動作か、従量課金サービスか |
| 推論エンジン | 入力処理、モデル実行、音声デコード | Qwen3-TTS、Chatterbox、CosyVoice等の実装 | コードのライセンス、必要GPU |
| モデル／重み | 実際に声を生成する学習済みパラメータ | Qwen3-TTS-1.7B、Irodori v4.1 Small | **重みの商用利用条件**。コードのMIT等とは別 |
| 声素材／プロファイル | 参照音声、話者埋め込み、追加学習データ | 収録した声、クローン声、プリセット声 | 本人同意、データ権利、公開・商用利用範囲 |

```text
Remotion
   └─ プロジェクト共通TTSアダプター
        ├─ Voicebox REST API ─ Qwen3-TTS / Chatterbox / Kokoro 等
        ├─ Irodori-TTS-Server ─ Irodori-TTS
        ├─ CosyVoice FastAPI ─ CosyVoice
        └─ GPT-SoVITS API ─ GPT-SoVITS
```

したがって「VoiceboxとQwen3-TTSのどちらを選ぶか」ではない。**Voiceboxの中でQwen3-TTSを使う**ことができ、必要ならVoiceboxを介さずQwen3-TTSを直接実行することもできる。

### 1.2 音声生成方式による分類

| 大分類 | 概要 | 長所 | 注意点 | 主な該当例 |
|---|---|---|---|---|
| 連結型／フォルマント型 | 録音片の連結、または音響規則で合成 | 軽量、挙動を予測しやすい | 自然さや表現力に限界。現在の本調査候補の中心ではない | 旧世代TTS |
| 音響モデル＋ボコーダー／VITS系 | 文字から音響特徴を作り、波形へ変換 | 高速で安定。話者専用モデルを作りやすい | 柔軟なゼロショット模倣はLLM型より弱い場合がある | Style-Bert-VITS2、VOICEVOX系 |
| 自己回帰／音声Codec言語モデル系 | 音声をトークンとして、文脈に沿って順次生成 | 自然さ、感情、文脈、ゼロショット模倣に強い | 反復、読み飛ばし、幻覚音声、生成速度に注意 | Qwen3-TTS、Fish Speech、GPT-SoVITS、CosyVoiceの一部 |
| Diffusion／Flow Matching系 | ノイズまたは連続分布から音声を復元 | 音質、話者類似、韻律制御に強い | 反復計算が必要な方式もある。新しい少ステップ方式では高速化 | F5-TTS、Irodori、OmniVoice、Meta Voicebox、Chatterboxの一部 |

現代のTTSは複数方式を組み合わせるため、この分類は排他的ではない。たとえば言語モデルで音声トークンを作り、別のFlow／Diffusion系デコーダーで波形化する構成もある。方式名だけで品質を決めず、同一文章・同一参照音声で比較する。

### 1.3 声の作り方による分類

| 種類 | 必要なもの | 向いている用途 |
|---|---|---|
| プリセット／マルチスピーカー | 用意された話者ID | すぐに安定した声を使う |
| ゼロショット音声クローン | 数秒～数十秒の参照音声、通常は追加学習なし | 収録声を短時間で再現、試作 |
| Few-shot／追加学習 | 数分以上の音声と学習工程 | 同一キャラクターを長期運用、再現性を上げる |
| Voice Design | 「若い、落ち着いた、明るい」等の文章指定 | 実在人物に依存しないオリジナル声の設計 |

なお、**TTS（文字→音声）**、**VC（音声→別の声）**、**STT（音声→文字）**は別機能である。吹替ワークフローは通常、STT→翻訳→TTS、必要に応じてVCを組み合わせる。

### 1.4 本調査における「無料」の条件

無料とは、クラウドAPIの無料枠ではなく、**ローカルで生成回数に上限がなく、1文字・1分ごとの従量課金がないこと**を指す。ただし、コード、モデル重み、声素材、生成物、統合アプリの各ライセンスは別々に確認する。GPU購入費、電気代、ストレージ、保守工数も0円ではない。

## 2. Voiceboxとの関係性

ここでいうVoiceboxは、Jamie Pine氏のオープンソース版 **Voicebox: Local-first AI voice studio** を指す。これは単体のTTS基盤モデルではなく、複数のローカルTTSエンジンを共通UI・APIで扱う**デスクトップアプリ／オーケストレーション層**である。

| 項目 | Voiceboxの位置づけ |
|---|---|
| 種別 | ローカル優先のAI音声制作アプリ。Tauri＋React、Python FastAPI、SQLite |
| 料金 | アプリはMIT。ローカル生成の従量課金なし |
| 主な機能 | モデルのダウンロードとキャッシュ、声プロファイル、複数参照音声、生成キュー、長文分割とクロスフェード、履歴・テイク管理、エフェクト、STT、MCP |
| 外部連携 | ローカルREST API。RemotionからHTTPで呼び出せる |
| 同梱対応エンジン | Qwen3-TTS、Qwen CustomVoice、LuxTTS、Chatterbox Multilingual、Chatterbox Turbo、TADA、Kokoro |
| 本調査候補で未対応 | Irodori-TTS、CosyVoice、GPT-SoVITS、OmniVoice、Fish Speech、F5-TTS、XTTS-v2 |
| 最大の注意 | VoiceboxがMITでも、内部で使う**各モデル重みのライセンスは変わらない** |

VoiceboxはQwen3-TTSやChatterboxをGUIで試聴し、声プロファイルを作り、API化する用途に非常に相性がよい。一方、Irodori、CosyVoice、GPT-SoVITSまで一つに統合できる完成済み万能ランタイムではない。未対応モデルはVoiceboxの `TTSBackend` を実装して追加できるが、開発・追従コストが生じる。

本件では、Remotion側に薄い共通アダプターを置き、`Voicebox`、`Irodori-TTS-Server`、`CosyVoice FastAPI`、`GPT-SoVITS API` を差し替え可能にする構成を推奨する。これならVoiceboxの便利な制作UIを使いつつ、未対応モデルや将来のモデル変更にも対応できる。

> [!warning] 同名モデルとの区別
> Metaが2023年に発表した研究モデル **Voicebox** は別物である。Meta VoiceboxはFlow Matchingを使う多言語の音声生成・編集研究で、当時モデルとコードは一般公開されなかった。今回のローカル導入候補でいうVoiceboxは、GitHub上の `jamiepine/voicebox` アプリを意味する。

## 3. 結論

### 今回の推奨順位

| 順位 | 推奨モデル | 採用理由 | 主用途 |
|---:|---|---|---|
| 1 | **Qwen3-TTS 1.7B Base / VoiceDesign** | 日英、3秒クローン、Voice Design、感情・韻律指示、Apache-2.0のバランスが最もよい | 日英共通のオリジナルキャラクター |
| 2 | **Chatterbox Multilingual V3** | MIT、23言語、ゼロショットクローン、導入が簡単、比較的軽量 | 最短で日英ローカルTTSを構築 |
| 3 | **CosyVoice 3 0.5B** | Apache-2.0、日英、クロスリンガルクローン、指示制御、公式FastAPI | 高品質な自動生成サーバー |
| 4 | **Irodori-TTS v4.1 Small** | 日本語特化、MIT、Voice Design、感情・絵文字制御、48kHz | 日本語キャラクター版の品質優先 |
| 5 | **GPT-SoVITS V2Pro系** | MIT、5秒ゼロショット／1分Few-shot、日英、少量学習時の声質再現が強い | 収録した声優の声を作り込む |
| 6 | **OmniVoice** | Apache-2.0、600以上の言語、短い参照音声、高速 | 将来、多数言語へ展開する場合 |

**一本だけ選ぶなら Qwen3-TTS 1.7B。** ただし日本語のみのキャラクター性・感情表現を最優先する場合は Irodori-TTS、8GB前後のGPUで導入を簡単にしたい場合は Chatterboxを先に試す。

### 本採用から外す候補

| モデル | 理由 |
|---|---|
| **Fish Speech** | 研究・非商用は無料だが、商用利用はFish Audioとの別契約が必要 |
| **F5-TTS公式重み** | コードはMITだが、公式F5-TTS v1 Base重みはCC BY-NC 4.0で非商用限定 |
| **XTTS-v2** | モデルはCPMLで非商用限定。Coqui終了後は商用ライセンスを新規購入できない状態 |

YouTube収益化、スポンサー動画、販売作品、業務利用は通常「商用」と考え、本採用から外すのが安全である。

### 実際に発生するローカル費用

- 既にGPU搭載PCがある場合、追加費用は主に電気代とストレージだけ。
- 電気代の概算は `GPUを含む平均消費電力(kW) × 生成時間(h) × 電力単価(円/kWh)`。
- 例として平均300W、月30時間、31円/kWhなら、`0.3 × 30 × 31 = 279円/月`。
- 音声を一度生成してキャッシュすれば、動画の再レンダーではTTS計算を繰り返さない。
- GPUを新規購入する場合は、まず所有PCで0.6B／0.5Bモデルを試し、不足した場合だけ更新する。

## 6. モデル別詳細

### 6.1 Qwen3-TTS — 総合第一候補

[公式リポジトリ](https://github.com/QwenLM/Qwen3-TTS) / Apache-2.0

- 10言語：中国語、英語、日本語、韓国語、独語、仏語、露語、葡語、西語、伊語。
- 0.6Bと1.7Bを提供。1.7Bは品質優先、0.6BはVRAMと速度優先。
- `Base` は約3秒の参照音声からゼロショットクローン。
- `VoiceDesign` は文章から架空の声を作成。
- `CustomVoice` は既成声と自然言語による演技指示。
- ストリーミング対応。公式は最短97msの初回音声出力を掲げる。
- 単一話者ファインチューニング手順も公式公開。

```bash
conda create -n qwen3-tts python=3.12 -y
conda activate qwen3-tts
pip install -U qwen-tts
```

**選び方:** オリジナル声を文章から作るなら1.7B VoiceDesign。声優の収録音声を使うなら1.7B Base。8GB級GPUでは0.6Bまたは量子化実装を先に試す。

### 6.2 Chatterbox Multilingual V3 — 導入の簡単さ

[公式リポジトリ](https://github.com/resemble-ai/chatterbox) / MIT

- 0.5B、23以上の言語、日本語・英語対応。
- 参照音声を指定するゼロショット声クローン。
- V3はV2より話者類似性、自然さ、不要な反復・幻覚を改善。
- 生成音声にはPerTh透かしが埋め込まれる。
- NVIDIAの最適化実装では多言語版の目安が約3.5GB VRAM。通常のPyTorch版は余裕を見て6GB以上から試す。

```bash
pip install chatterbox-tts
```

**長所:** インストールが簡単で、MITのため商用利用を整理しやすい。**短所:** Qwen3-TTSやIrodoriほど自由なVoice Designは主機能ではない。

### 6.3 CosyVoice 3 — APIサーバー運用

[公式リポジトリ](https://github.com/QwenAudio/CosyVoice) / Apache-2.0

- Fun-CosyVoice3-0.5Bは日本語・英語を含む9言語。
- ゼロショット／クロスリンガル声クローン。
- 言語、感情、速度、音量などの指示制御。
- テキスト入力と音声出力の双方向ストリーミング。公式は150ms級の低遅延を掲げる。
- 公式リポジトリにFastAPI、gRPC、Docker、vLLM、TensorRT-LLMの導線がある。

```bash
git clone --recursive https://github.com/FunAudioLLM/CosyVoice.git
cd CosyVoice
conda create -n cosyvoice -y python=3.10
conda activate cosyvoice
pip install -r requirements.txt
```

**長所:** Remotion用の常駐ローカルAPIへしやすい。**短所:** 依存関係とサブモジュールが多く、Windows単体よりWSL2／Docker向き。

### 6.4 Irodori-TTS v4.1 Small — 日本語キャラクター第一候補

[公式コード](https://github.com/Aratako/Irodori-TTS) / [モデルカード](https://huggingface.co/Aratako/Irodori-TTS-v4.1-Small) / MIT

- 約0.8B、日本語専用、48kHz。
- 文章だけのVoice Design、参照音声クローン、Voice Designとクローンの併用。
- 絵文字で笑い、ため息、咳などの感情・非言語表現を制御。
- v4.1は継続時間予測を改善。短い1クリップより、可能なら約30秒以上のきれいな参照音声が推奨。
- 低メモリ向けINT8 / INT4 / FP8版あり。
- [Irodori-TTS-Server](https://github.com/Aratako/Irodori-TTS-Server) はOpenAI互換の `POST /v1/audio/speech`、長文分割、複数音声形式に対応。

```bash
curl http://localhost:8088/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{"model":"irodori-tts","input":"こんにちは。","voice":"sample","response_format":"wav"}' \
  --output speech.wav
```

**長所:** 日本語キャラ声を文章から作る用途に非常に合う。**短所:** 英語を生成できないため、英語版はQwen3-TTS、Chatterbox、CosyVoice等との二段構成になる。

### 6.5 GPT-SoVITS — Few-shot学習

[公式リポジトリ](https://github.com/RVC-Boss/GPT-SoVITS) / MIT

- 日本語、英語、中国語、韓国語、広東語。
- 約5秒の参照音声でゼロショット、約1分の収録でFew-shot学習。
- 音声分割、ノイズ除去、ASR、ラベル校正、学習をWebUIに統合。
- APIは標準で `127.0.0.1:9880`。WAV / OGG / AAC、ストリーミングに対応。
- V2ProはV2／V4との比較を踏まえ、品質と計算量のバランスを狙った系統。

```bash
git clone https://github.com/RVC-Boss/GPT-SoVITS.git
cd GPT-SoVITS
conda create -n GPTSoVits python=3.10
conda activate GPTSoVits
bash install.sh --device CU128 --source HF
python api.py -a 127.0.0.1 -p 9880
```

**長所:** 少量収録からキャラクター固有の声を作り込める。**短所:** 学習データ準備と版選択が複雑。Voice Designはない。

### 6.6 OmniVoice — 多数言語

[公式リポジトリ](https://github.com/k2-fsa/OmniVoice) / Apache-2.0

- 600以上の言語、ゼロショット声クローン、Voice Design。
- 3〜10秒の参照音声を推奨。参照テキストを省略するとWhisperで自動転写。
- 音声プロンプトを保存し、以後の生成で再利用できる。
- CUDA、Apple Silicon MPS、Intel XPUに対応。公式Web UIとCLIあり。
- クロスリンガル生成では参照音声の言語アクセントが残る場合がある。
- Voice Designの訓練は主に中国語・英語で、日本語ではVoice Cloneの方が安定。

```bash
pip install omnivoice
omnivoice-demo --ip 127.0.0.1 --port 8001
```

**長所:** 対応言語数が圧倒的。**短所:** 日英だけならQwen3-TTSやCosyVoiceの方が狙いを絞りやすい。

### 6.7 Fish Speech — 品質は高いが商用無料ではない

[公式リポジトリ](https://github.com/fishaudio/fish-speech) / Fish Audio Research License

- S2系は日本語・英語をTier 1言語として扱い、多言語クローンと表現力に優れる。
- ローカル推論、WebUI、Server、Dockerを提供。
- 2026-03-07更新のライセンスでは、研究・非商用は無償だが、商用目的はFish Audioとの書面による別ライセンスが必要。

**判定:** 無収益の個人検証には使えるが、「無料で収益化動画を量産」という条件には合わない。

### 6.8 F5-TTS — 公式重みは非商用

[公式リポジトリ](https://github.com/SWivid/F5-TTS) / コードMIT・公式重みCC BY-NC 4.0

- Flow Matchingによる高品質なゼロショットTTS。公式Baseは中国語・英語中心。
- 日本語はコミュニティモデルを別途選ぶ必要があり、その重みのライセンスも個別確認。
- pip、Docker、Gradio、Triton / TensorRT-LLMの導線がある。

```bash
pip install f5-tts
f5-tts_infer-gradio --host 127.0.0.1
```

**判定:** 品質研究用には有力だが、公式重みを収益化コンテンツへ使えない。

### 6.9 XTTS-v2 — 現在は優先度が低い

[モデルカード](https://huggingface.co/coqui/XTTS-v2) / CPML

- 日本語・英語を含む16言語のゼロショット声クローン。
- 導入例と周辺ツールは多く、比較的軽い。
- ただしモデルと出力はCPML上、非商用利用に限定される。
- Coqui終了後、新しい商用ライセンスを購入する窓口が存在しないとメンテナ側が説明している。

**判定:** 技術的にも世代が古く、商用ライセンス上の出口がないため、新規採用しない。

## 7. GPU別の現実的な候補

VRAMは実装、量子化、音声長、同時実行数で変わるため目安。最初は必ず短文で実測する。

| GPU環境 | 現実的な候補 | コメント |
|---|---|---|
| CPUのみ | Chatterbox Nano（英語のみ）、量子化実装 | 日本語の量産は遅いため非推奨 |
| 4〜6GB | Chatterbox Multilingual最適化版、Qwen3-TTS 0.6B量子化 | 長文・並列実行は厳しい |
| 8GB | **Chatterbox V3、Qwen3-TTS 0.6B、CosyVoice 0.5B、GPT-SoVITS** | 最初の検証ライン |
| 12GB | **Qwen3-TTS 1.7B、Irodori量子化／半精度、各0.5Bモデル** | 品質優先の実用ライン |
| 16GB以上 | 上記すべて、長文、複数常駐、学習 | 制作パイプライン向け |

## 8. 用途別の構成案

### 案A：日英を同じ声で、無料で作る

1. Qwen3-TTS 1.7B VoiceDesignで架空の声を作る。
2. 作った音声をBaseモデルの参照音声として固定する。
3. 日本語・英語を同じ参照声から生成する。
4. 同じ参照音声、seed、設定を保存する。

### 案B：日本語のキャラクター性を最優先

1. Irodori-TTS Voice Designで日本語声を作る。
2. 30〜60秒分の良質な基準音声を作り、キャラクターのマスター音声として保存する。
3. 日本語版はIrodoriで生成。
4. 英語版はそのマスター音声をQwen3-TTS / Chatterbox / CosyVoiceへ渡してクロスリンガルクローンする。

この構成は日英で完全に同じ音響モデルではないため、同一人物感を必ず聴感評価する。

### 案C：声優収録から作り込む

1. 本人同意を得て、ノイズの少ない日本語・英語音声を各言語で収録する。
2. 5〜10秒の即時比較はQwen3-TTS / Chatterbox / CosyVoice。
3. 1分以上を用意できるならGPT-SoVITSもFew-shot学習して比較する。
4. 声質、発音、感情、再現性の合計点で採用する。

## 9. Remotion連携

### 推奨アーキテクチャ

```text
script/ja.json + script/en.json
        ↓
ローカルTTSアダプター
  qwen | chatterbox | cosyvoice | irodori | gpt-sovits
        ↓
public/audio/{locale}/{content-hash}.wav
        ↓
音声長・字幕・口パク用メタデータ
        ↓
Remotion <Audio> + <Sequence>
```

レンダー中にTTSを実行せず、レンダー前のNode.jsスクリプトからローカルAPIへ一度だけ送る。`text + locale + model + checkpoint + voice + settings` のSHA-256をファイル名にし、再レンダー時はキャッシュを使う。

```ts
import {mkdir, writeFile} from 'node:fs/promises';
import path from 'node:path';

export async function synthesizeOpenAICompatible({
  baseUrl,
  text,
  voice,
  output,
}: {
  baseUrl: string;
  text: string;
  voice: string;
  output: string;
}) {
  const response = await fetch(`${baseUrl}/v1/audio/speech`, {
    method: 'POST',
    headers: {'Content-Type': 'application/json'},
    body: JSON.stringify({
      model: 'local-tts',
      input: text,
      voice,
      response_format: 'wav',
    }),
  });
  if (!response.ok) throw new Error(`${response.status}: ${await response.text()}`);
  await mkdir(path.dirname(output), {recursive: true});
  await writeFile(output, Buffer.from(await response.arrayBuffer()));
}
```

Irodoriは公式互換サーバーをそのまま使える。Qwen3-TTS、Chatterbox、OmniVoiceは薄いFastAPIラッパーか、既存のOpenAI互換コミュニティサーバーを固定バージョンで導入する。CosyVoiceは公式FastAPI、GPT-SoVITSは公式 `api.py` をアダプターで吸収する。

## 10. 同一条件ベンチマーク

### テスト対象

- Qwen3-TTS 1.7B Base
- Chatterbox Multilingual V3
- CosyVoice 3 0.5B
- Irodori-TTS v4.1（日本語のみ）
- GPT-SoVITS V2Pro
- OmniVoice

### 共通入力

- 同じ話者の無音・BGMなし参照音声を5秒、10秒、30秒の3種類用意。
- 48kHz WAV原本を保存し、各モデルの推奨形式へ変換。
- 日本語：通常、喜び、怒り、悲しみ、早口、固有名詞、数字。
- 英語：同内容の自然なローカライズ。直訳は使わない。
- 各条件3回生成し、偶然よい出力だけを選ばない。

### 採点

| 項目 | 重み | 内容 |
|---|---:|---|
| 日本語自然性 | 5 | アクセント、漢字読み、間、長文安定性 |
| 英語自然性 | 5 | 発音、アクセント、流暢さ |
| 話者類似性 | 5 | 日本語内、英語内、日英間の同一人物感 |
| キャラクター性 | 5 | 声質、感情、演技幅、再現性 |
| 内容忠実性 | 5 | 脱落、反復、幻覚、読み間違い |
| 速度 | 3 | 生成時間、モデル起動時間 |
| VRAM | 3 | 最大使用量、OOMの有無 |
| API運用 | 4 | バッチ、エラー処理、長文、再起動 |
| ライセンス | 5 | 商用無料、追加モデル、データの条件 |

## 11. 最終提案

1. **最初に入れる3つ:** Qwen3-TTS 1.7B、Chatterbox Multilingual V3、Irodori-TTS v4.1。
2. **API運用比較用:** CosyVoice 3を追加。
3. **声優音声を作り込む場合:** GPT-SoVITS V2Proを追加。
4. **多数言語展開が決まった場合:** OmniVoiceを追加。
5. Fish Speech、F5-TTS公式重み、XTTS-v2は非商用の品質比較にだけ使用し、採用候補には入れない。
6. 最終決定は公開デモの印象ではなく、同一参照音声・同一台本・同一GPUで生成したブラインド試聴で行う。
